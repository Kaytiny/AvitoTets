# AvitoTets
Гибридный ретривер: лексический канал **BM25** + семантический канал **dense (дообученный
multilingual-E5)** склеиваются ранговым методом **RRF**, поверх чего накладываются
аддитивные поправки — штраф за «чужую» категорию, мягкий штраф по рейтингу из текстовых
фильтров запроса и бонус за совпадение локации.
## 1. Какие данные и признаки я использовал и почему

### Признаки запроса (колонки search_*)
- search_query — основной текст запроса (короткий: «автоподбор», «скупка телевизоров»).
- search_infm_params_text — текстовые фильтры («Рейтинг 4 звезды и выше», «Вид услуги …»);
  сильно сужают намерение и используются и как текст или источник числового порога рейтинга
- search_category — категория поиска
- search_location_id, search_is_delivery_search — география поиска и флаг доставки
  используются как фильтр близости 

### Признаки объявления (колонки item_*)
- item_title_raw, item_infm_params_text, item_description_raw (берутся первые 400 символов —
  дальше в услугах обычно шаблонный текст и контакты, мало несущие смысла);
- item_category_id, item_microcat_id — систематика объявления
- item_location_id — география; item_rating — рейтинг по отзывам 

### Почему именно эти признаки
Запросы в задаче короткие, поэтому одного семантического сигнала недостаточно и
нужны точные слова ,которые они идут в лексический канал BM25; атрибуты категории и локации, которые в
train почти всегда согласованы у позитивов одного запроса , они дают сигнал «сузить
эффективный корпус» без ранжирующего списка.
Текст объявления и запроса собирается в единый мешок слов, куда дополнительно кладутся
id категории/подкатегории , чтобы лексический канал мог сопоставить категорию напрямую при
совпадении систем представления

. Какие модели и алгоритмы я применил

Архитектура — **гибридная кандидатная генерация с ранговой склейкой**. Поток:

```
запрос ─┬─► [Канал BM25]        ─┐
        ├─► [Канал dense (E5)]   ├─► RRF-склейка рангов ─► + штраф категории
        └─► (категория/локация/  │                         + штраф рейтинга
             рейтинг как поправки)┘                         + бонус локации  ─► топ‑50
```

### Канал 1 — BM25 (лексический)
Собственная векторизованная реализация Okapi BM25 (class BM25): CountVectorizer по мешку
слов объявления + предвычисленная sparse‑матрица коэффициентов
idf·(k1+1)·tf / (tf + K_d), где K_d = k1·(1 − b + b·|d|/avgdl), k1 = 1.5, b = 0.75.
Скоринг запроса сведён к одному sparse‑произведению Q @ Cᵀ,
без градиентного спуска

### Канал 2 — dense (семантический)
Open‑source модель **intfloat/multilingual-e5-base** (HuggingFace; разворачивается локально
через sentence-transformers, без API).
Дообучение под задачу через **MultipleNegativesRankingLoss** на положительных парах
(query, positive) с in‑batch негативами; обучение на подвыборке
FAST_STEPS · TRAIN_BS пар (по умолчанию 2000 шагов и примерно 64 тысяч пар) по кривой loss это точка
насыщения, полный объём не даёт значимого прироста Recall. Поиск по
эмбеддингам FAISS  по косинусной близости (эмбеддинги L2‑нормализованы)

## Склейка — RRF
Финальный скор кандидата: `score = Σ_каналов 1 / (k_ch + rank_ch)` плюс аддитивные поправки.
RRF выбран потому, что он масштабно‑независим: не требует подбора весов между разнородными
скорамы BM25 и косинусной близостью, берётся просто топ‑50 по итоговому скору
# 3. Как я проверял качество решения до отправки

### Сплит без утечки
train делится по  запросу (_sig = search_query + location + category +
infm_params + delivery), а не по строкам: 10 % групп уходят в валидацию. Dense‑модель и
категорийный приор для валидации обучаются только на train, поэтому позитивы
валидации в обучение не попадают


## 4. Какие типы ошибок я нашёл при анализе и что с ними сделал
### 1 Recall@50 ≈ 0.20 у исходного решения, ошибкой было только dense‑ретривер: би‑энкодер не ловит точные слова коротких запросов. Добавил лексический канал BM25 главный одиночный прирост Recall
### 2 Вредное дообучение, Hard negatives майни той же слабой базовой моделью  и релеванты учились плохо. Перешел на `MultipleNegativesRankingLoss` с in‑batch негативами и обучение на подвыборке в точке насыщения loss'а
### 3 Тот же низкий Recall. Полностью игнорировались категория и локация: ранжирование шло по всему корпусу из 189 тысяч и тонуло в шуме чужих категорий. Добавил категориальный штраф и бонус локации
